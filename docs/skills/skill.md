# 投融资法律尽调skill

# 我把投资机构的法律尽调，拆成了两个可以分阶段使用的 Skill

最近，我一直在尝试解决一个问题：

**能不能把投资机构内部积累的法律尽调方法，沉淀成一套真正可复用的AI工作流？**

这里说的不是让AI简单生成一份通用尽调清单，也不是上传几十份材料后一键拼出一份看起来很完整的报告，而是让它尽可能贴近投资机构实际开展法律尽调的过程：

- BP阶段，快速识别影响立项的法律问题；
- 项目行业不同，适用不同的监管逻辑和业务资质要求；
- 收到第一轮资料后，识别资料缺口、事实矛盾和新增风险；
- 补充资料回传后，持续更新问题；
- 资料基本齐备时，形成一份具有事实基础和法律论证的完整尽调报告；
- 最后再把重要风险转化为交割条件、承诺、赔偿和投后事项。

经过多轮试跑和修改，我最终没有把所有任务塞进一个庞大的Skill，而是拆成了两个相互衔接、可以独立使用的法律尽调Skill：

1. **初期投资法律尽调 Skill**
2. **完整投资尽调法律 Skill**

两个Skill已经整理在同一个GitHub仓库中，但分别对应不同的项目阶段，可以单独安装和维护。

GitHub地址：[https://github.com/Hellyai/investment-legal-dd-skill]

## 一、为什么要拆成两个 Skill

一开始，我尝试用一个Skill处理从BP预审到完整报告的全部工作。

理论上，这样看起来很完整；实际使用时却暴露出几个问题。

### 1. 系统任务过长，执行效率下降

BP预审和完整法律尽调本质上不是同一种工作。

BP阶段更关心的是：

- 创始团队是否存在明显风险；
- 核心技术从哪里来；
- 是否涉及前雇主、高校或研究院的权利；
- 股权和历史融资有没有明显问题；
- 实际业务是否需要特定资质；
- 是否存在关联交易或者业务主体错位。

而完整尽调还要逐项核查：

- 各集团主体的设立和历史沿革；
- 历轮融资及股东特殊权利；
- 股权、实缴、付款和工商登记是否一致；
- 重大业务合同及履行情况；
- 知识产权权属和争议；
- 业务资质是否覆盖实际经营活动；
- 关联交易、劳动用工、资产负债、诉讼处罚及境外经营等事项。

如果全部放入同一个Skill，AI每次都要判断当前处于哪个阶段、需要调用哪些规则、应当生成什么文件，容易造成执行缓慢和输出混乱。

### 2. 不同行业容易被错误混同

早期测试中出现过两个比较典型的问题：

- 先进制造项目被套用了半导体、芯片行业的法规；
- 核聚变项目因为使用了AI仿真或智能控制技术，被错误识别为AI项目。

问题的根源是：AI容易根据BP中的关键词判断行业，而不是根据公司的商业化对象和实际经营活动判断。

因此，我为Skill增加了一个非常重要的前置步骤：

**行业不能由AI静默决定，必须先由投资机构确认。**

行业判断不再看公司是否提到“AI”“芯片”或者“智能制造”，而是依次判断：

1. 客户实际为什么产品或服务付费；
2. 公司的核心资产是什么；
3. 公司实际从事研发、制造、运营、销售还是许可；
4. 监管规则直接规制的对象是什么；
5. AI、芯片、软件等是否只是辅助技术。

目前主要设置了AI、半导体/芯片、先进制造、核聚变等行业包，并设置出海叠加层。没有匹配行业时，可以明确归入“其他/待研究”，而不是强行选择最接近的行业。

### 3. “完整报告”和“投决会红旗报告”被混在了一起

法律尽调报告通常很长。

传统律所式完整报告主要回答：

> 公司历史上发生了什么，这些事项是否合法，目前的法律状态如何。

投资机构内部的红旗报告则主要回答：

> 投资人现在应当担心什么，应当通过什么交易条件控制风险。

这两种报告都很有价值，但不能相互替代。

此前试跑时，AI生成的报告虽然覆盖了主要章节，也给出了交割条件、陈述保证、专项赔偿和投后监控建议，但整体更像一份十几页的投资决策及交易闭环简版，缺少：

- 各主体逐项历史沿革；
- 历轮融资协议及特殊权利梳理；
- 股权、实缴和付款勾稽；
- 重大合同和知识产权明细；
- 具体法律规则的适用分析；
- 证据索引和未决事项台账。

因此，现在的Skill已经明确区分：

- **正式完整版法律尽调报告**
- **投决会红旗PPT**

正式报告完成后，只有客户明确同意，并确认哪些问题需要进入投委会材料，才会另行生成红旗PPT。

## 二、两个 Skill 分别怎么使用

## 1. 初期投资法律尽调 Skill

适用于：

- BP；
- 立项报告；
- 路演材料；
- 创始团队介绍；
- 项目早期公开信息。

它的使用流程是：

### 第一步：确认行业

AI先在对话框中展示：

- 公司的核心产品或服务；
- 商业化对象；
- 核心资产；
- 实际经营活动；
- 推荐主行业；
- 容易混淆但建议排除的行业；
- 需要进一步确认的事实。

这一阶段只在对话框中完成，不生成报告。

### 第二步：展示尽调关注重点

行业确认后，AI结合项目阶段、行业特点和创业背景，在对话框中展示5至12项最值得关注的问题，例如：

- 创始人是否受前雇主竞业限制；
- 核心技术是否可能属于职务成果；
- 高校或研究院成果转化程序是否完成；
- 历史融资是否存在代持、回购或未交割事项；
- 实际经营主体与融资主体是否一致；
- 核心业务是否需要特定资质；
- 是否存在创始人控制的关联主体；
- 业务是否依赖单一客户、供应商或第三方技术。

投资机构可以增加、删除或调整这些关注重点。

### 第三步：生成初步尽调清单

客户确认关注重点后，Skill才生成初步尽调清单Word。

清单不是机械套用通用模板，而是根据：

- 行业；
- 项目阶段；
- 创始团队背景；
- 商业模式；
- 已经发现的潜在问题；

调整资料要求和优先级。

## 2. 完整投资尽调法律 Skill

适用于：

- 已收到第一轮尽调资料；
- 需要识别缺失资料；
- 需要提出补充问题；
- 需要形成专项法律分析；
- 需要出具完整法律尽调报告。

它包含两条使用路径。

### 路径一：资料尚不完整

第一步，AI读取回传材料，建立资料、事实、问题和处理动作之间的对应关系。

第二步，生成一份：

**《尽调重点及问题分析》Word**

内容包括：

- 已经核实的事实；
- 证据及证据强弱；
- 缺失或冲突的资料；
- 适用法律规则；
- 法律分析；
- 对投资的影响；
- 风险等级；
- 建议处理方式。

第三步，等待客户确认。

投资机构可以确认：

- 哪些问题判断准确；
- 哪些问题需要提高或降低等级；
- 哪些事项需要进一步核查；
- 哪些问题不需要继续追问；
- 哪些风险应转化为交易条件。

第四步，客户确认后，再生成：

**《补充尽调清单》Word**

也就是说，问题分析和补充清单之间设置了一个人工确认节点，避免AI自动生成大量与投资判断不一致的补充要求。

### 路径二：生成正式完整版报告

出现以下任一条件时，可以进入完整报告模式：

- 资料达到正式报告出具门槛；
- 客户明确要求出具完整报告。

完整报告不以页数作为唯一标准，而是检查是否真正完成：

- 集团主体逐一调查；
- 历史沿革连续还原；
- 历轮融资逐轮梳理；
- 协议、付款、实缴和登记相互勾稽；
- 重大合同及履行情况核验；
- 核心知识产权权属和来源分析；
- 核心团队历史限制调查；
- 业务资质与实际业务匹配；
- 法律依据及规则适用分析；
- 风险、整改和交易条款闭环；
- 证据索引及未决资料披露。

报告可以采用两种结构：

- **综合展开型**：更接近传统成熟律所的完整报告；
- **问题前置型**：先呈现主要法律问题，再完整展开事实和论证。

两种格式的区别只是叙述顺序，不改变调查深度。

## 三、它试图解决哪些问题

### 1. 解决通用清单缺乏针对性的问题

同一份法律尽调清单不可能同时适用于AI、芯片、先进制造、核聚变和出海项目。

Skill先确认行业，再根据实际业务活动匹配行业准入、业务资质和监管要求。

### 2. 解决项目阶段错配的问题

没有业务合同的早期项目，不应机械要求提供大量成熟业务资料；已经形成规模收入的项目，也不能只关注团队和技术来源。

两个Skill按照项目阶段分别处理，避免调查重点失衡。

### 3. 解决资料回传后“只整理、不分析”的问题

AI最容易做的是文件分类，最难的是判断：

- 哪些事实已经得到证明；
- 哪些只是公司陈述；
- 哪些文件相互矛盾；
- 哪些缺口可能影响投资；
- 应当怎样转化为补充资料和交易条件。

完整版Skill通过资料、事实、问题和交易动作台账，尽量让每个风险能够回到证据，也能够进入后续处理。

### 4. 解决完整报告过度简化的问题

Skill不再把“覆盖全部章节”视为完成。

完整报告必须逐主体、逐轮次、逐事项展开，并形成融资、股权、合同、知识产权、资质、关联交易及未决事项等附表。

### 5. 解决法律风险与交易文件脱节的问题

尽调发现重大问题后，不能停留在“建议关注”。

Skill要求将重大和高风险进一步转化为：

- 交易否决条件；
- 交割先决条件；
- 交割后承诺；
- 陈述与保证；
- 专项赔偿；
- 价格或估值调整；
- 第三方同意；
- 投后整改及持续监控。

## 四、目前仍然存在的问题

这套Skill并不能替代律师，也不能解决法律尽调中的所有问题。

### 1. 资料真实性仍需要人工判断

AI可以识别文件之间是否矛盾，但不能仅凭扫描件确认：

- 文件是否真实签署；
- 印章是否真实；
- 付款是否实际发生；
- 合同是否存在未披露的补充安排；
- 公司是否提供了完整资料。

必要时仍需要原件核验、访谈、函证和第三方调查。

### 2. 法律和监管信息具有时效性

业务资质、出口管制、数据、制裁和境外产品合规变化较快。正式结论必须核验至报告基准日，并优先使用法律法规、主管部门文件和官方数据库。

### 3. 境外法律问题可能需要当地律师

Skill可以建立司法辖区和业务活动矩阵、识别问题并提出核验路径，但不能在缺乏当地法律意见时，对复杂境外监管事项作无保留结论。

### 4. 报告质量仍然取决于资料质量

资料严重缺失时，即使客户要求生成完整版报告，也必须充分披露：

- 哪些事项无法确认；
- 假设某种事实成立时可能产生什么风险；
- 对投资判断和交易安排有什么影响。

不能因为需要交付报告，就把未知事实写成确定结论。

### 5. 行业包仍需要继续积累

现有行业包只能覆盖已经沉淀的方法。面对新的细分行业，仍需要重新研究行业准入、业务资质和监管规则，不能为了完成分类而强行套用已有行业包。

## 五、这套 Skill 的价值是什么

我认为，它最大的价值不是“30分钟生成一份尽调报告”。

真正的价值是把投资机构内部原本分散在律师经验、项目文件和个人判断中的方法，转化为一套可以反复执行、持续更新的工作流。

它能够帮助投资团队：

- 在立项阶段更早发现关键法律红旗；
- 减少行业识别错误和通用清单滥用；
- 提高第一轮资料清单的针对性；
- 让每轮补充尽调都有明确依据；
- 让事实、证据、风险和交易处理相互对应；
- 在完整报告与投委会材料之间建立清晰分工；
- 降低不同项目、不同经办人之间的工作标准差异；
- 将项目经验逐步沉淀为机构自己的法律尽调能力。

AI可以提高整理、检索和初稿生成效率，但法律尽调真正有价值的部分，始终是：

**事实是否查清，证据是否足够，法律规则是否适用，以及风险应当如何影响投资决策。**

这套Skill所做的，就是尽量让AI服务于这四个问题，而不是只生成一份看起来完整的文件。
