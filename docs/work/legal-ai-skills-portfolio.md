# 把法律经验做成可以反复调用的 AI Skills

最近一段时间，我把自己在投融资交易中反复遇到的几类工作，陆续整理成了三个可以独立使用的 AI Skill。

我想做的并不是让 AI “写得更快”，而是把那些原本只存在于个人经验里的判断方法，拆成有边界、有步骤、能复核的工作流程。这样换一个项目、换一份文件，仍然可以沿着同一套逻辑继续工作。

## 01｜交易文件审阅：先识别角色，再进入条款

第一组是 **VC/PE 投资文件审阅 Skills**，覆盖 Term Sheet、投资协议、股东协议和交割文件。

它不会拿到文件就直接逐条改字，而是先确认文件类型、审阅方身份、交易轮次和目标，再决定需要调用哪套审阅规则。除了提示条款风险，也会检查交易结构、权利是否完整、文件之间是否一致，以及尽调问题有没有落实到交割条件。

[查看交易法律 Skills →](https://github.com/Hellyai/transaction-legal-skills-)

## 02｜Cap Table：把复杂计算变成可追溯的过程

第二组是 **Cap Table Skill**。

它用于处理增资、老股转让、混合交易、多轮融资和连续反摊薄计算。相比只给一个最终持股比例，我更在意每一步的口径是否说得清楚：本轮投前股本是多少、价格如何调整、补偿股数从哪里来，以及各张表之间能不能勾稽一致。

最终交付的不只是数字，也包括可以复核的计算过程。

[查看 Cap Table Skill →](https://github.com/Hellyai/cap-table-skill)

## 03｜法律尽调：按项目阶段决定工作深度

第三组是 **投融资法律尽调 Skill**。

我把它拆成两个阶段：项目只有 BP 或立项材料时，先识别影响投资判断的明显红旗，形成尽调重点和首轮文件清单；收到成批资料后，再进入完整尽调，处理资料缺失、事实矛盾、补充问题、风险闭环和正式报告。

这样做，是为了避免材料还很少时就生成一份看似完整、实际上缺少事实依据的报告。

[查看投融资法律尽调 Skill →](https://github.com/Hellyai/investment-legal-dd-skill)

## 三个 Skill 背后，其实是同一种工作方法

虽然它们分别处理文件审阅、股权计算和法律尽调，但底层逻辑很接近：

1. 先确认角色、材料和任务边界；
2. 把复杂工作拆成能够执行的步骤；
3. 保留来源、计算口径和待核实事项；
4. 让结果能够被专业人员继续检查和接管。

这些 Skill 还会继续更新。对我来说，真正值得沉淀的不是某一次 AI 输出，而是完成项目之后，能不能把其中的方法留下来，下一次继续使用。
